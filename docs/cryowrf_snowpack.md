Поддержка добавлена поверх универсального Dataset. WRFDataset наследует её, DatasetSeries делегирует чтение исходному файлу с локальным индексом времени. Поддержка обычных WRF, met_em, CF-NetCDF, staggered U/V, атмосферных профилей и GIS сохранена. Новые зависимости не добавлены.

## Определение и чтение

Поле считается Snowpack-layer полем по наличию **имени** размерности `snowpack_layers_stag`, включая неизвестные численные диагностические переменные. Порядок размерностей и размеры сетки не фиксируются. `SN_QI_SUBLIM3D` и `SN_QI_SUBLHEAT3D` обрабатываются по фактическим размерностям; их имена не превращают атмосферное поле в Snowpack.

`vertical_profile()` выбирает один timestep, одну ячейку и вертикальный срез через xarray `isel` под `NETCDF_LOCK`. Атмосферные профили также читаются одним вектором; правила атмосферных координат GHT/PRES сохранены.

`SN_NLAYERS` читается для каждой точки и времени. Профиль возвращает первые `n` элементов. При `n=0` возвращается пустой вектор, интерфейс сообщает отсутствие активного профиля; значения соседнего времени не копируются. Отрицательные/слишком большие значения ограничиваются диапазоном `[0, capacity]` с предупреждением. Дробные значения округляются вниз, NaN/Infinity считаются неактивными и сопровождаются предупреждением.

Если `SN_NLAYERS` отсутствует, число активных элементов нельзя доказать: обычный вектор сохраняется, окно явно предупреждает, что показаны сохранённые уровни с непроверенной активностью. Отдельная кнопка инспектора активируется только при наличии положительного счётчика.

Карты, `point_value()` и временные ряды Snowpack-полей используют отдельную маску: ячейка/время с `SN_NLAYERS <= selected_layer` получает NaN. Активные соседние ячейки сохраняются. Маска применяется также к derived-плотностям и статическим Snowpack-полям с меняющимся счётчиком; кэш учитывает timestep. Исходные xarray-данные и NetCDF не меняются.

## Глубина и профиль

Для положительной конечной `SN_THICK` в активных элементах:

```text
bottom_depth = cumsum(SN_THICK)
center_depth = bottom_depth - SN_THICK / 2
```

Порядок соответствует заданной пользователем схеме: элемент 0 находится у поверхности. График использует центр элемента, 0 расположен сверху, глубина увеличивается вниз. Отсутствующая, отрицательная, нулевая или нечисловая толщина даёт предупреждение и переход к индексам элементов. Атмосферным профилям эта схема не назначается.

Окно «Профиль снега · SNOWPACK» содержит координаты, Grid X/Y, UTC timestamp, SNOWH/SNOW/TSK/SN_NLAYERS, выбор всех доступных свойств и таблицу только активных элементов. Таблица read-only, включает толщину, глубину, температуру, доли, обе плотности, массу, RG/RB/DD/SP, код зерна, raw deposition Julian и MK. Выбор строки показывает сумму долей и предупреждение при отклонении более 0.02 или пропущенных значениях.

В инспекторе карты «Снежный покров» читается независимо от добавленных слоёв, в worker; существующие значения видимых слоёв остаются в своей таблице. Окно профиля является снимком выбранного времени: для другого времени его нужно открыть снова.

## Диагностика и научные ограничения

| Величина | Формула | Единицы |
| --- | --- | --- |
| Snow Density — вклад льда | `917 * SN_VOLI` | kg m-3 |
| Layer bulk density | `917 * SN_VOLI + 1000 * SN_VOLW` | kg m-3 |
| Layer mass per unit area | `SN_THICK * (917 * SN_VOLI + 1000 * SN_VOLW)` | kg m-2 |
| Средняя кажущаяся плотность покрова | `SNOW / SNOWH`, только при `SNOWH > 0` | kg m-3 |

Это диагностические оценки, не новые состояния модели. Snow Density исключает жидкую воду. Масса выводится только в профиле, отдельный map layer для неё не добавлен. Исходное поле с совпадающим именем имеет приоритет перед derived-величиной.

SN_VOLI/SN_VOLW/SN_VOLV отображаются как доли с единицей `1`; raw значения и исходные `%` в атрибутах/VariableInfo остаются неизменными. Нет автоматического умножения/деления на 100.

SN_GRAINTYPE — дискретный числовой код: qualitative `tab20`, исходные ячейки, без фильтра/контуров/интерполяции. Профиль и временной ряд показывают отдельные точки и целочисленные подписи. Легенды карты и PNG содержат «Grain type code N». Значения кодов не расшифровываются. Палитра имеет 20 цветов; при большом числе кодов цвета могут повторяться, точные коды сохраняются в легенде и инспекторе.

SN_DEPD остаётся raw Julian number: конвенция Snowpack/MeteoIO по предоставленному файлу не подтверждена, календарный перевод не добавлен. SN_CDOT имеет нейтральную подпись «SNOWPACK CDot / internal loading-rate variable». SNPACK_STAB подписан как параметр **атмосферной** устойчивости. Оценка лавинной опасности, механической устойчивости и вероятность лавины не вычисляются.

## Приёмка на реальном wrfout

В текущем workspace есть реальные met_em, но нет wrfout с CRYOWRF/SNOWPACK. Реальный профиль capacity=500 и модельные конвенции пока проверены только по спецификации пользователя и синтетическому файлу; это остаётся обязательной научной/пользовательской приёмкой.

Открыть файл или серию через меню «Файл», добавить SNOWH/SNOW/TSK/SN_NLAYERS, переключить время, выбрать снежную ячейку и открыть «Профиль SNOWPACK». Проверить соответствие числа строк SN_NLAYERS, surface-first порядок SN_THICK, температуру по глубине, доли/сумму, RG/RB и дискретные коды. В свойствах слоя выбрать Snowpack layer и проверить NaN там/тогда, где счётчик меньше или равен индексу; построить ряд и экспортировать PNG. Для нулевого history record должен показываться пустой профиль.

Нужна проверка на реальном файле: ориентация профиля и единицы SN_THICK; реальные размерности и единицы диагностик; смысл/конвенция SN_DEPD; таблица кодов SN_GRAINTYPE, если впоследствии требуется расшифровка. Программа ничего не угадывает и не исправляет в модели.
