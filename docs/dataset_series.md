# Серии файлов модели и панели

AvalancheView открывает один файл или совместимую серию через единый интерфейс данных. Для серии все даты на временной шкале относятся к одному пространственному домену, независимо от физического файла.

## Анализ исходных файлов

Перед реализацией исследованы все 7 файлов `demo_data/met_em.d01.*.nc`. Данные не изменялись. Во всех файлах:

- `TITLE = OUTPUT FROM METGRID V4.0`, `FLAG_METGRID = 1`, `grid_id = 1`;
- `Time = 1`, время хранится в `Times`; числовых координат `Time` и `XTIME` нет;
- массовая сетка `south_north = 99`, `west_east = 99`, staggered dimensions = 100;
- `XLAT_M/XLONG_M` имеют одинаковые значения во всех файлах; также присутствуют координаты U, V и углов сетки;
- `MAP_PROJ = 2`, полярная стереографическая проекция, `DX = DY = 9000 m`, `TRUELAT1 ≈ 42.445`, `STAND_LON ≈ 43.355`;
- широты 38.375034–46.471401°, долготы 37.444160–49.265839°;
- 34 `num_metgrid_levels`, по 4 почвенных уровня, дополнительные измерения категорий 3/12/16/21/132;
- 94 исходные переменные с совпадающими размерностями и единицами.

| Файл | Внутреннее время `Times`, UTC |
|---|---|
| met_em.d01.2025-02-18_12%3A00%3A00.nc | 18.02.2025 12:00 |
| met_em.d01.2025-02-18_18%3A00%3A00.nc | 18.02.2025 18:00 |
| met_em.d01.2025-02-19_00%3A00%3A00.nc | 19.02.2025 00:00 |
| met_em.d01.2025-02-19_06%3A00%3A00.nc | 19.02.2025 06:00 |
| met_em.d01.2025-02-19_12%3A00%3A00.nc | 19.02.2025 12:00 |
| met_em.d01.2025-02-19_18%3A00%3A00.nc | 19.02.2025 18:00 |
| met_em.d01.2025-02-20_00%3A00%3A00.nc | 20.02.2025 00:00 |

`SIMULATION_START_DATE` в этих met_em меняется вместе с датой `Times`, поэтому для METGRID этот атрибут не используется как идентификатор отдельного запуска. Для WRF проверяется совпадение `SIMULATION_START_DATE`.

Файлы содержат `SNOWH [m]`, `TT [K]`, `RH [%]`, `PSFC [Pa]`, `HGT_M [meters MSL]`, staggered `UU/VV [m s-1]` и `COSALPHA/SINALPHA`. `U10/V10` отсутствуют. Для ветра добавлена вычисляемая переменная **Wind Speed (UU/VV)** с выбором вертикального уровня, усреднением staggered-сетки и поворотом компонент. `PRES`, `SM`, `ST` и `SOIL_LAYERS` не имеют заполненного атрибута units; приложение сохраняет эту информацию как есть.

Полные размерности, метаданные и единицы каждой переменной каждого файла сохраняет:

```powershell
.\.venv\Scripts\python.exe tools/inspect_model_files.py
```

Результат: [demo_data_metadata.json](demo_data_metadata.json).

## Открытие и просмотр

1. **Файл → Открыть серию файлов…**: выберите несколько `.nc`, `met_em*` или `wrfout*`. Порядок выбора не влияет на порядок дат.
2. **Файл → Открыть папку модели…**: приложение сканирует подходящие файлы непосредственно в выбранной папке и предлагает найденные серии. Разные domains, сетки и запуски WRF показаны отдельно.
3. Можно перетащить несколько файлов или папку из Explorer. При открытии одного `met_em`/`wrfout` через диалог или drag & drop приложение проверяет соседние файлы и предлагает открыть совместимую серию. Самостоятельно добавлять их к открытому dataset оно не будет.
4. Дважды нажмите **SNOWH** в списке переменных и включите воспроизведение на временной шкале.
5. Для ветра met_em добавьте **Wind Speed (UU/VV)**, выберите **Wind vectors** или **Wind barbs** и вертикальный уровень в свойствах слоя. Для WRF доступны также **Wind Speed 10m** и **Wind Speed (U/V)** при наличии соответствующих компонент.
6. Выберите точку на карте. В инспекторе откройте вкладку **Временной ряд**, выберите переменную и нажмите **Временной ряд**. График появится в панели **Графики** и охватит всю серию.
7. ПКМ по панели данных → **Информация о наборе данных** показывает тип, domain, размеры сетки, даты, проекцию и доступность переменных.

Запуск сразу на имеющейся серии из PowerShell:

```powershell
.\.venv\Scripts\python.exe main.py (Get-ChildItem demo_data/met_em*.nc).FullName
```

При частичной совместимости серия использует объединение переменных. Доступность показана как число дат из общего количества. Переменная с отличающимися единицами или размерностями не используется на конфликтующем шаге. Карта и инспектор сообщают о недоступном значении, в графике ставится NaN.

Повреждённые файлы пропускаются с подробным отчётом и записью в лог. Дубли времени разрешаются детерминированно: используется первый файл по отсортированному абсолютному пути, остальные источники сообщаются в предупреждении. Все существующие даты сохраняются; для интервалов больше обычного шага серии временная шкала показывает «пропуск». Графики используют реальные datetime, поэтому расстояния между датами отражают интервалы времени.

## Память и потоки

`FileEntry` содержит метаданные, даты и подпись координат; погодные поля при анализе не загружаются. `DatasetCompatibilityChecker` сравнивает тип, domain, сетку, проекцию, координаты, запуск WRF и схемы переменных.

`DatasetSeries` хранит отображение глобального времени на файл и локальный timestep. Одновременно открыто не более 3 источников. Общий LRU погодных срезов ограничен 128 MiB и тремя недавно использованными датами. Координатные массивы нужны для проверки сетки; файлы после анализа закрываются.

Чтение кадров и предварительная подготовка следующего шага выполняются в QThreadPool; работа с Qt и Matplotlib остаётся в GUI thread. Анимация ожидает готовность очередного кадра, чтобы при медленном диске даты не сменялись без отображения карты. Временной ряд читает только выбранную ячейку каждого источника. Доступ к NetCDF/HDF сериализован.

Слои, палитры, прозрачность, уровни, режимы и границы карты сохраняются при смене источника. Состояние источников инкапсулировано в модели данных; приложение пока использует один основной набор данных.

## Управление панелями

**Вид → Панели** содержит стандартные `toggleViewAction()` для данных, слоёв, свойств, инспектора, временной шкалы и графиков. Кнопки основной панели используют те же QAction. Закрытие dock скрывает его и сохраняет содержимое. Графики можно вернуть вместе с уже построенными кривыми.

**Вид → Панели инструментов** восстанавливает основную панель и панель навигации карты. **Вид → Восстановить расположение панелей** возвращает основные панели на места и показывает их.

QSettings сохраняет геометрию и версионированное состояние. Некорректный, старый layout или состояние со всеми скрытыми dock заменяется стандартным расположением.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m pytest --basetemp=verification/pytest-series -o cache_dir=verification/pytest-cache
.\.venv\Scripts\python.exe -m ruff check . --no-cache
.\.venv\Scripts\python.exe tools/verify_series_ui.py
```

Последняя команда выполняет сценарий через Qt actions на реальных файлах `demo_data`, включая анимацию скаляра и ветра, график точки, закрытие и возвращение dock, перезапуск и восстановление layout. Выбор файлов для QFileDialog подставляется программно; это автоматизированная проверка GUI. Результаты: [series_verification.json](series_verification.json), [скриншот](series_screenshot.png). Контрольные суммы входных файлов сравниваются до и после проверки.

Ограничения: серия требует распознаваемых календарных дат; файлы без дат доступны через открытие одного файла. Движущаяся сетка внутри multi-time файла отклоняется при сборке серии. Встроенные режимы карты продолжают работать; линии тока и вертикальные разрезы пока не были реализованы в исходном приложении. Не добавлялись установка 3D-библиотек и одновременное отображение нескольких datasets.
